You are completing the design of a small book sorting row of carts with 5 carts.

The carts are: KORU, FOLA, FALU, GOJI, JARA. Books move KORU -> FOLA -> FALU -> GOJI -> JARA.
There are 7 moving steps:
- "juki" carries each KORU tray to a FOLA tray.
- "dupu" is an internal rearrangement of FOLA: it carries each FOLA tray to a FOLA tray.
- "rali" carries each FOLA tray to a FALU tray.
- "bapu" is an internal rearrangement of FALU: it carries each FALU tray to a FALU tray.
- "rozi" carries each FALU tray to a GOJI tray.
- "kovi" is an internal rearrangement of GOJI: it carries each GOJI tray to a GOJI tray.
- "rizi" carries each GOJI tray to a JARA tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "juki" and then "dupu" lands on the same tray as running "juki" alone.
     ("dupu" leaves every tray that "juki" produces unchanged.)
R1.2 Running "dupu" and then "rali" gives the same result as running "rali" alone.
     ("rali" cannot tell whether "dupu" was applied first.)
R1.3 Running "dupu" twice in a row leaves every FOLA tray exactly where it started.
R2.1 Running "rali" and then "bapu" lands on the same tray as running "rali" alone.
     ("bapu" leaves every tray that "rali" produces unchanged.)
R2.2 Running "bapu" and then "rozi" gives the same result as running "rozi" alone.
     ("rozi" cannot tell whether "bapu" was applied first.)
R2.3 Running "bapu" twice in a row leaves every FALU tray exactly where it started.
R3.1 Running "rozi" and then "kovi" lands on the same tray as running "rozi" alone.
     ("kovi" leaves every tray that "rozi" produces unchanged.)
R3.2 Running "kovi" and then "rizi" gives the same result as running "rizi" alone.
     ("rizi" cannot tell whether "kovi" was applied first.)
R3.3 Running "kovi" twice in a row leaves every GOJI tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- KORU has exactly one tray, called n1.
- JARA has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (FOLA, FALU, GOJI):
D1.1 FOLA must be a finite set with at most 3 trays.
D1.2 "dupu" must NOT be the do-nothing move (it must move at least one FOLA tray).
D2.1 FALU must be a finite set with at most 3 trays.
D2.2 "bapu" must NOT be the do-nothing move (it must move at least one FALU tray).
D3.1 GOJI must be a finite set with at most 3 trays.
D3.2 "kovi" must NOT be the do-nothing move (it must move at least one GOJI tray).

Your task: give one complete concrete design of the middle carts.

Answer format bound: designs with up to 4 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

FOLA = {q1_1, ..., q1_k}
juki: n1 -> <FOLA tray>
dupu: q1_1 -> <FOLA tray>, ..., q1_k -> <FOLA tray>
FALU = {q2_1, ..., q2_k}
rali: q1_1 -> <FALU tray>, ... (one entry per FOLA tray)
bapu: q2_1 -> <FALU tray>, ..., q2_k -> <FALU tray>
GOJI = {q3_1, ..., q3_k}
rozi: q2_1 -> <GOJI tray>, ... (one entry per FALU tray)
kovi: q3_1 -> <GOJI tray>, ..., q3_k -> <GOJI tray>
rizi: q3_1 -> <JARA tray>, ... (one entry per GOJI tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
