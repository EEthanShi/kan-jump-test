You are completing the design of a small book sorting row of carts with 3 carts.

The carts are: DUJA, SITA, BOTA. Books move DUJA -> SITA -> BOTA.
There are 3 moving steps:
- "rozi" carries each DUJA tray to a SITA tray.
- "zinu" is an internal rearrangement of SITA: it carries each SITA tray to a SITA tray.
- "japa" carries each SITA tray to a BOTA tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "rozi" and then "zinu" lands on the same tray as running "rozi" alone.
     ("zinu" leaves every tray that "rozi" produces unchanged.)
R1.2 Running "zinu" and then "japa" gives the same result as running "japa" alone.
     ("japa" cannot tell whether "zinu" was applied first.)
R1.3 Running "zinu" twice in a row leaves every SITA tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- DUJA has exactly 2 trays, called n1, n2.
- BOTA has exactly 2 trays, called s1, s2.
- The observed end-to-end behavior of the row sends n1 to s1, n2 to s1.

Requirements for the middle cart (SITA):
D1.1 List the trays of SITA in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "zinu" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D1.3 List the "rozi" table entries in DUJA tray order n1, n2.
D1.4 List the "japa" table entries in SITA tray order q1_1, q1_2, ...

Your task: give one complete concrete design of the middle cart.

Answer format bound: designs with up to 4 trays in the middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
use tray names q1_1, q1_2, ... for the middle cart):

SITA = {q1_1, ..., q1_k}
rozi: n1 -> <SITA tray>, n2 -> <SITA tray>
zinu: q1_1 -> <SITA tray>, ..., q1_k -> <SITA tray>
japa: q1_1 -> <BOTA tray>, ... (one entry per SITA tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
