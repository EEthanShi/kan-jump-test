You are completing the design of a small book sorting row of carts with 5 carts.

The carts are: MOGA, MURU, BODU, SOKO, MOJI. Books move MOGA -> MURU -> BODU -> SOKO -> MOJI.
There are 7 moving steps:
- "pano" carries each MOGA tray to a MURU tray.
- "suki" is an internal rearrangement of MURU: it carries each MURU tray to a MURU tray.
- "nolu" carries each MURU tray to a BODU tray.
- "dudo" is an internal rearrangement of BODU: it carries each BODU tray to a BODU tray.
- "mavi" carries each BODU tray to a SOKO tray.
- "goba" is an internal rearrangement of SOKO: it carries each SOKO tray to a SOKO tray.
- "kodi" carries each SOKO tray to a MOJI tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "pano" and then "suki" lands on the same tray as running "pano" alone.
     ("suki" leaves every tray that "pano" produces unchanged.)
R1.2 Running "suki" and then "nolu" gives the same result as running "nolu" alone.
     ("nolu" cannot tell whether "suki" was applied first.)
R1.3 Running "suki" three times in a row leaves every MURU tray exactly where it started.
R2.1 Running "nolu" and then "dudo" lands on the same tray as running "nolu" alone.
     ("dudo" leaves every tray that "nolu" produces unchanged.)
R2.2 Running "dudo" and then "mavi" gives the same result as running "mavi" alone.
     ("mavi" cannot tell whether "dudo" was applied first.)
R2.3 Running "dudo" three times in a row leaves every BODU tray exactly where it started.
R3.1 Running "mavi" and then "goba" lands on the same tray as running "mavi" alone.
     ("goba" leaves every tray that "mavi" produces unchanged.)
R3.2 Running "goba" and then "kodi" gives the same result as running "kodi" alone.
     ("kodi" cannot tell whether "goba" was applied first.)
R3.3 Running "goba" twice in a row leaves every SOKO tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- MOGA has exactly one tray, called n1.
- MOJI has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (MURU, BODU, SOKO):
D1.1 List the trays of MURU in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "suki" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D2.1 List the trays of BODU in increasing index order q2_1, q2_2, ... in its set line.
D2.2 List the "dudo" table entries in tray order q2_1, q2_2, ..., one entry per tray.
D3.1 List the trays of SOKO in increasing index order q3_1, q3_2, ... in its set line.
D3.2 List the "goba" table entries in tray order q3_1, q3_2, ..., one entry per tray.

Your task: give one complete concrete design of the middle carts.

Answer format bound: designs with up to 5 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

MURU = {q1_1, ..., q1_k}
pano: n1 -> <MURU tray>
suki: q1_1 -> <MURU tray>, ..., q1_k -> <MURU tray>
BODU = {q2_1, ..., q2_k}
nolu: q1_1 -> <BODU tray>, ... (one entry per MURU tray)
dudo: q2_1 -> <BODU tray>, ..., q2_k -> <BODU tray>
SOKO = {q3_1, ..., q3_k}
mavi: q2_1 -> <SOKO tray>, ... (one entry per BODU tray)
goba: q3_1 -> <SOKO tray>, ..., q3_k -> <SOKO tray>
kodi: q3_1 -> <MOJI tray>, ... (one entry per SOKO tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
