You are completing the design of a small toy sorting line with 3 stations.

The stations are: SOVI, BAPI, VOSU. Toys move SOVI -> BAPI -> VOSU.
There are 3 moving steps:
- "vufo" carries each SOVI slot to a BAPI slot.
- "dugo" is an internal reshuffle of BAPI: it carries each BAPI slot to a BAPI slot.
- "guji" carries each BAPI slot to a VOSU slot.

The line's operating rules. These must hold exactly, slot by slot:
R1.1 Running "vufo" and then "dugo" lands on the same slot as running "vufo" alone.
     ("dugo" leaves every slot that "vufo" produces unchanged.)
R1.2 Running "dugo" and then "guji" gives the same result as running "guji" alone.
     ("guji" cannot tell whether "dugo" was applied first.)
R1.3 Running "dugo" twice in a row leaves every BAPI slot exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- SOVI has exactly 2 slots, called n1, n2.
- VOSU has exactly 1 slot, called s1.
- The observed end-to-end behavior of the line sends n1 to s1, n2 to s1.

Requirements for the middle station (BAPI):
D1.1 BAPI must be a finite set with at most 2 slots.
D1.2 List the "dugo" table entries in slot order q1_1, q1_2, ..., one entry per slot.
D1.3 "vufo" must carry different SOVI slots to different BAPI slots.
D1.4 List the "guji" table entries in BAPI slot order q1_1, q1_2, ...

Your task: give one complete concrete design of the middle station.

Answer format bound: designs with up to 4 slots in the middle station
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every slot and every table entry;
use slot names q1_1, q1_2, ... for the middle station):

BAPI = {q1_1, ..., q1_k}
vufo: n1 -> <BAPI slot>, n2 -> <BAPI slot>
dugo: q1_1 -> <BAPI slot>, ..., q1_k -> <BAPI slot>
guji: q1_1 -> <VOSU slot>, ... (one entry per BAPI slot)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
