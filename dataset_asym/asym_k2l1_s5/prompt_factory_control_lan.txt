You are completing the design of a small toy sorting line with 3 stations.

The stations are: PUTO, BUKU, FOVI. Toys move PUTO -> BUKU -> FOVI.
There are 3 moving steps:
- "malo" carries each PUTO slot to a BUKU slot.
- "ruru" is an internal reshuffle of BUKU: it carries each BUKU slot to a BUKU slot.
- "voka" carries each BUKU slot to a FOVI slot.

The line's operating rules. These must hold exactly, slot by slot:
R1.1 Running "malo" and then "ruru" lands on the same slot as running "malo" alone.
     ("ruru" leaves every slot that "malo" produces unchanged.)
R1.2 Running "ruru" and then "voka" gives the same result as running "voka" alone.
     ("voka" cannot tell whether "ruru" was applied first.)
R1.3 Running "ruru" twice in a row leaves every BUKU slot exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- PUTO has exactly 2 slots, called n1, n2.
- FOVI has exactly 1 slot, called s1.
- The observed end-to-end behavior of the line sends n1 to s1, n2 to s1.

Requirements for the middle station (BUKU):
D1.1 BUKU must be a finite set with at most 2 slots.
D1.2 List the "ruru" table entries in slot order q1_1, q1_2, ..., one entry per slot.
D1.3 "malo" must carry different PUTO slots to different BUKU slots.
D1.4 List the "voka" table entries in BUKU slot order q1_1, q1_2, ...

Your task: give one complete concrete design of the middle station.

Answer format bound: designs with up to 4 slots in the middle station
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every slot and every table entry;
use slot names q1_1, q1_2, ... for the middle station):

BUKU = {q1_1, ..., q1_k}
malo: n1 -> <BUKU slot>, n2 -> <BUKU slot>
ruru: q1_1 -> <BUKU slot>, ..., q1_k -> <BUKU slot>
voka: q1_1 -> <FOVI slot>, ... (one entry per BUKU slot)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
