You are completing the design of a small book sorting row of carts with 3 carts.

The carts are: KISI, BIMI, GUPA. Books move KISI -> BIMI -> GUPA.
There are 3 moving steps:
- "pofi" carries each KISI tray to a BIMI tray.
- "jono" is an internal rearrangement of BIMI: it carries each BIMI tray to a BIMI tray.
- "tila" carries each BIMI tray to a GUPA tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "pofi" and then "jono" lands on the same tray as running "pofi" alone.
     ("jono" leaves every tray that "pofi" produces unchanged.)
R1.2 Running "jono" and then "tila" gives the same result as running "tila" alone.
     ("tila" cannot tell whether "jono" was applied first.)
R1.3 Running "jono" twice in a row leaves every BIMI tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- KISI has exactly 2 trays, called n1, n2.
- GUPA has exactly 2 trays, called s1, s2.
- The observed end-to-end behavior of the row sends n1 to s1, n2 to s1.

Requirements for the middle cart (BIMI):
D1.1 BIMI must be a finite set with at most 2 trays.
D1.2 List the "jono" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D1.3 "pofi" must carry different KISI trays to different BIMI trays.
D1.4 List the "tila" table entries in BIMI tray order q1_1, q1_2, ...

Your task: give one complete concrete design of the middle cart.

Answer format bound: designs with up to 4 trays in the middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
use tray names q1_1, q1_2, ... for the middle cart):

BIMI = {q1_1, ..., q1_k}
pofi: n1 -> <BIMI tray>, n2 -> <BIMI tray>
jono: q1_1 -> <BIMI tray>, ..., q1_k -> <BIMI tray>
tila: q1_1 -> <GUPA tray>, ... (one entry per BIMI tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
