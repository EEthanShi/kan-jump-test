You are completing the design of a small book sorting row of carts with 3 carts.

The carts are: ROVU, BALO, PAJI. Books move ROVU -> BALO -> PAJI.
There are 3 moving steps:
- "rana" carries each ROVU tray to a BALO tray.
- "tugo" is an internal rearrangement of BALO: it carries each BALO tray to a BALO tray.
- "fado" carries each BALO tray to a PAJI tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "rana" and then "tugo" lands on the same tray as running "rana" alone.
     ("tugo" leaves every tray that "rana" produces unchanged.)
R1.2 Running "tugo" and then "fado" gives the same result as running "fado" alone.
     ("fado" cannot tell whether "tugo" was applied first.)
R1.3 Running "tugo" twice in a row leaves every BALO tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- ROVU has exactly 1 tray, called n1.
- PAJI has exactly 2 trays, called s1, s2.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle cart (BALO):
D1.1 BALO must be a finite set with at most 1 tray.
D1.2 List the "tugo" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D1.3 "rana" must carry different ROVU trays to different BALO trays.
D1.4 List the "fado" table entries in BALO tray order q1_1, q1_2, ...

Your task: give one complete concrete design of the middle cart.

Answer format bound: designs with up to 3 trays in the middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
use tray names q1_1, q1_2, ... for the middle cart):

BALO = {q1_1, ..., q1_k}
rana: n1 -> <BALO tray>
tugo: q1_1 -> <BALO tray>, ..., q1_k -> <BALO tray>
fado: q1_1 -> <PAJI tray>, ... (one entry per BALO tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
