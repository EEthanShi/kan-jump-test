You are completing the design of a small book sorting row of carts with 5 carts.

The carts are: MULA, DOFA, LIZI, NUFO, GASA. Books move MULA -> DOFA -> LIZI -> NUFO -> GASA.
There are 7 moving steps:
- "puza" carries each MULA tray to a DOFA tray.
- "safo" is an internal rearrangement of DOFA: it carries each DOFA tray to a DOFA tray.
- "niki" carries each DOFA tray to a LIZI tray.
- "nuvo" is an internal rearrangement of LIZI: it carries each LIZI tray to a LIZI tray.
- "tilo" carries each LIZI tray to a NUFO tray.
- "viko" is an internal rearrangement of NUFO: it carries each NUFO tray to a NUFO tray.
- "sada" carries each NUFO tray to a GASA tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "puza" and then "safo" lands on the same tray as running "puza" alone.
     ("safo" leaves every tray that "puza" produces unchanged.)
R1.2 Running "safo" and then "niki" gives the same result as running "niki" alone.
     ("niki" cannot tell whether "safo" was applied first.)
R1.3 Running "safo" three times in a row leaves every DOFA tray exactly where it started.
R2.1 Running "niki" and then "nuvo" lands on the same tray as running "niki" alone.
     ("nuvo" leaves every tray that "niki" produces unchanged.)
R2.2 Running "nuvo" and then "tilo" gives the same result as running "tilo" alone.
     ("tilo" cannot tell whether "nuvo" was applied first.)
R2.3 Running "nuvo" twice in a row leaves every LIZI tray exactly where it started.
R3.1 Running "tilo" and then "viko" lands on the same tray as running "tilo" alone.
     ("viko" leaves every tray that "tilo" produces unchanged.)
R3.2 Running "viko" and then "sada" gives the same result as running "sada" alone.
     ("sada" cannot tell whether "viko" was applied first.)
R3.3 Running "viko" twice in a row leaves every NUFO tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- MULA has exactly one tray, called n1.
- GASA has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (DOFA, LIZI, NUFO):
D1.1 DOFA must be a finite set with at most 1 tray.
D1.2 List the "safo" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D2.1 LIZI must be a finite set with at most 1 tray.
D2.2 List the "nuvo" table entries in tray order q2_1, q2_2, ..., one entry per tray.
D3.1 NUFO must be a finite set with at most 1 tray.
D3.2 List the "viko" table entries in tray order q3_1, q3_2, ..., one entry per tray.

Your task: give one complete concrete design of the middle carts.

Answer format bound: designs with up to 4 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

DOFA = {q1_1, ..., q1_k}
puza: n1 -> <DOFA tray>
safo: q1_1 -> <DOFA tray>, ..., q1_k -> <DOFA tray>
LIZI = {q2_1, ..., q2_k}
niki: q1_1 -> <LIZI tray>, ... (one entry per DOFA tray)
nuvo: q2_1 -> <LIZI tray>, ..., q2_k -> <LIZI tray>
NUFO = {q3_1, ..., q3_k}
tilo: q2_1 -> <NUFO tray>, ... (one entry per LIZI tray)
viko: q3_1 -> <NUFO tray>, ..., q3_k -> <NUFO tray>
sada: q3_1 -> <GASA tray>, ... (one entry per NUFO tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
