You are completing the design of a small book sorting row of carts with 6 carts.

The carts are: SINU, NAJO, SOTI, ZUZU, POBA, ZUTI. Books move SINU -> NAJO -> SOTI -> ZUZU -> POBA -> ZUTI.
There are 9 moving steps:
- "funi" carries each SINU tray to a NAJO tray.
- "rito" is an internal rearrangement of NAJO: it carries each NAJO tray to a NAJO tray.
- "gudu" carries each NAJO tray to a SOTI tray.
- "dolu" is an internal rearrangement of SOTI: it carries each SOTI tray to a SOTI tray.
- "fuvu" carries each SOTI tray to a ZUZU tray.
- "tapi" is an internal rearrangement of ZUZU: it carries each ZUZU tray to a ZUZU tray.
- "vovo" carries each ZUZU tray to a POBA tray.
- "vopi" is an internal rearrangement of POBA: it carries each POBA tray to a POBA tray.
- "mutu" carries each POBA tray to a ZUTI tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "funi" and then "rito" lands on the same tray as running "funi" alone.
     ("rito" leaves every tray that "funi" produces unchanged.)
R1.2 Running "rito" and then "gudu" gives the same result as running "gudu" alone.
     ("gudu" cannot tell whether "rito" was applied first.)
R1.3 Running "rito" three times in a row leaves every NAJO tray exactly where it started.
R2.1 Running "gudu" and then "dolu" lands on the same tray as running "gudu" alone.
     ("dolu" leaves every tray that "gudu" produces unchanged.)
R2.2 Running "dolu" and then "fuvu" gives the same result as running "fuvu" alone.
     ("fuvu" cannot tell whether "dolu" was applied first.)
R2.3 Running "dolu" twice in a row leaves every SOTI tray exactly where it started.
R3.1 Running "fuvu" and then "tapi" lands on the same tray as running "fuvu" alone.
     ("tapi" leaves every tray that "fuvu" produces unchanged.)
R3.2 Running "tapi" and then "vovo" gives the same result as running "vovo" alone.
     ("vovo" cannot tell whether "tapi" was applied first.)
R3.3 Running "tapi" three times in a row leaves every ZUZU tray exactly where it started.
R4.1 Running "vovo" and then "vopi" lands on the same tray as running "vovo" alone.
     ("vopi" leaves every tray that "vovo" produces unchanged.)
R4.2 Running "vopi" and then "mutu" gives the same result as running "mutu" alone.
     ("mutu" cannot tell whether "vopi" was applied first.)
R4.3 Running "vopi" twice in a row leaves every POBA tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- SINU has exactly one tray, called n1.
- ZUTI has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (NAJO, SOTI, ZUZU, POBA):
D1.1 List the trays of NAJO in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "rito" table entries in tray order q1_1, q1_2, ..., one entry per tray.
