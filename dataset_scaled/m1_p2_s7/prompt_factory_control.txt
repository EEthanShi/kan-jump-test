You are completing the design of a small toy sorting line with 3 stations.

The stations are: SUNU, SUDA, PAMI. Toys move SUNU -> SUDA -> PAMI.
There are 3 moving steps:
- "maso" carries each SUNU slot to a SUDA slot.
- "sivi" is an internal reshuffle of SUDA: it carries each SUDA slot to a SUDA slot.
- "dofu" carries each SUDA slot to a PAMI slot.

The line's operating rules. These must hold exactly, slot by slot:
R1.1 Running "maso" and then "sivi" lands on the same slot as running "maso" alone.
     ("sivi" leaves every slot that "maso" produces unchanged.)
R1.2 Running "sivi" and then "dofu" gives the same result as running "dofu" alone.
     ("dofu" cannot tell whether "sivi" was applied first.)
R1.3 Running "sivi" twice in a row leaves every SUDA slot exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- SUNU has exactly one slot, called n1.
- PAMI has exactly one slot, called s1.
- The observed end-to-end behavior of the line sends n1 to s1.

Requirements for the middle station (SUDA):
D1.1 SUDA must be a finite set with at most 1 slot.
D1.2 List the "sivi" table entries in slot order q1_1, q1_2, ..., one entry per slot.

Your task: give one complete concrete design of the middle station.

Answer format bound: designs with up to 4 slots per middle station
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every slot and every table entry;
for station number i in the row, use slot names qi_1, qi_2, ...):

SUDA = {q1_1, ..., q1_k}
maso: n1 -> <SUDA slot>
sivi: q1_1 -> <SUDA slot>, ..., q1_k -> <SUDA slot>
dofu: q1_1 -> <PAMI slot>, ... (one entry per SUDA slot)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
