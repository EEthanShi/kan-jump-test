You are completing the design of a small book sorting row of carts with 6 carts.

The carts are: MOLU, TIPU, SUZU, ZOSA, ZIRO, RADU. Books move MOLU -> TIPU -> SUZU -> ZOSA -> ZIRO -> RADU.
There are 9 moving steps:
- "nuja" carries each MOLU tray to a TIPU tray.
- "kigi" is an internal rearrangement of TIPU: it carries each TIPU tray to a TIPU tray.
- "ruju" carries each TIPU tray to a SUZU tray.
- "turu" is an internal rearrangement of SUZU: it carries each SUZU tray to a SUZU tray.
- "lubi" carries each SUZU tray to a ZOSA tray.
- "novi" is an internal rearrangement of ZOSA: it carries each ZOSA tray to a ZOSA tray.
- "poza" carries each ZOSA tray to a ZIRO tray.
- "vika" is an internal rearrangement of ZIRO: it carries each ZIRO tray to a ZIRO tray.
- "tifu" carries each ZIRO tray to a RADU tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "nuja" and then "kigi" lands on the same tray as running "nuja" alone.
     ("kigi" leaves every tray that "nuja" produces unchanged.)
R1.2 Running "kigi" and then "ruju" gives the same result as running "ruju" alone.
     ("ruju" cannot tell whether "kigi" was applied first.)
R1.3 Running "kigi" three times in a row leaves every TIPU tray exactly where it started.
R2.1 Running "ruju" and then "turu" lands on the same tray as running "ruju" alone.
     ("turu" leaves every tray that "ruju" produces unchanged.)
R2.2 Running "turu" and then "lubi" gives the same result as running "lubi" alone.
     ("lubi" cannot tell whether "turu" was applied first.)
R2.3 Running "turu" twice in a row leaves every SUZU tray exactly where it started.
R3.1 Running "lubi" and then "novi" lands on the same tray as running "lubi" alone.
     ("novi" leaves every tray that "lubi" produces unchanged.)
R3.2 Running "novi" and then "poza" gives the same result as running "poza" alone.
     ("poza" cannot tell whether "novi" was applied first.)
R3.3 Running "novi" three times in a row leaves every ZOSA tray exactly where it started.
R4.1 Running "poza" and then "vika" lands on the same tray as running "poza" alone.
     ("vika" leaves every tray that "poza" produces unchanged.)
R4.2 Running "vika" and then "tifu" gives the same result as running "tifu" alone.
     ("tifu" cannot tell whether "vika" was applied first.)
R4.3 Running "vika" twice in a row leaves every ZIRO tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- MOLU has exactly one tray, called n1.
- RADU has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (TIPU, SUZU, ZOSA, ZIRO):
D1.1 List the trays of TIPU in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "kigi" table entries in tray order q1_1, q1_2, ..., one entry per tray.
