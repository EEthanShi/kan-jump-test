You are completing the design of a small book sorting row of carts with 6 carts.

The carts are: FUPU, MUVU, ZIDI, MAPI, RIJI, LAGI. Books move FUPU -> MUVU -> ZIDI -> MAPI -> RIJI -> LAGI.
There are 9 moving steps:
- "gupo" carries each FUPU tray to a MUVU tray.
- "toja" is an internal rearrangement of MUVU: it carries each MUVU tray to a MUVU tray.
- "goni" carries each MUVU tray to a ZIDI tray.
- "tadi" is an internal rearrangement of ZIDI: it carries each ZIDI tray to a ZIDI tray.
- "loda" carries each ZIDI tray to a MAPI tray.
- "najo" is an internal rearrangement of MAPI: it carries each MAPI tray to a MAPI tray.
- "mofu" carries each MAPI tray to a RIJI tray.
- "pugo" is an internal rearrangement of RIJI: it carries each RIJI tray to a RIJI tray.
- "nugu" carries each RIJI tray to a LAGI tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "gupo" and then "toja" lands on the same tray as running "gupo" alone.
     ("toja" leaves every tray that "gupo" produces unchanged.)
R1.2 Running "toja" and then "goni" gives the same result as running "goni" alone.
     ("goni" cannot tell whether "toja" was applied first.)
R1.3 Running "toja" twice in a row leaves every MUVU tray exactly where it started.
R2.1 Running "goni" and then "tadi" lands on the same tray as running "goni" alone.
     ("tadi" leaves every tray that "goni" produces unchanged.)
R2.2 Running "tadi" and then "loda" gives the same result as running "loda" alone.
     ("loda" cannot tell whether "tadi" was applied first.)
R2.3 Running "tadi" three times in a row leaves every ZIDI tray exactly where it started.
R3.1 Running "loda" and then "najo" lands on the same tray as running "loda" alone.
     ("najo" leaves every tray that "loda" produces unchanged.)
R3.2 Running "najo" and then "mofu" gives the same result as running "mofu" alone.
     ("mofu" cannot tell whether "najo" was applied first.)
R3.3 Running "najo" twice in a row leaves every MAPI tray exactly where it started.
R4.1 Running "mofu" and then "pugo" lands on the same tray as running "mofu" alone.
     ("pugo" leaves every tray that "mofu" produces unchanged.)
R4.2 Running "pugo" and then "nugu" gives the same result as running "nugu" alone.
     ("nugu" cannot tell whether "pugo" was applied first.)
R4.3 Running "pugo" three times in a row leaves every RIJI tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- FUPU has exactly one tray, called n1.
- LAGI has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (MUVU, ZIDI, MAPI, RIJI):
D1.1 List the trays of MUVU in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "toja" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D2.1 List the trays of ZIDI in increasing index order q2_1, q2_2, ... in its set line.
D2.2 List the "tadi" table entries in tray order q2_1, q2_2, ..., one entry per tray.
D3.1 List the trays of MAPI in increasing index order q3_1, q3_2, ... in its set line.
D3.2 List the "najo" table entries in tray order q3_1, q3_2, ..., one entry per tray.
D4.1 List the trays of RIJI in increasing index order q4_1, q4_2, ... in its set line.
D4.2 List the "pugo" table entries in tray order q4_1, q4_2, ..., one entry per tray.

Your task: give one complete concrete design of the middle carts.
