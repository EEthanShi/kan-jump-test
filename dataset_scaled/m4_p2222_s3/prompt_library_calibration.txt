You are completing the design of a small book sorting row of carts with 6 carts.

The carts are: VUSA, PILO, TIBU, TUKI, GOMU, KOSA. Books move VUSA -> PILO -> TIBU -> TUKI -> GOMU -> KOSA.
There are 9 moving steps:
- "mago" carries each VUSA tray to a PILO tray.
- "doku" is an internal rearrangement of PILO: it carries each PILO tray to a PILO tray.
- "rifi" carries each PILO tray to a TIBU tray.
- "gamu" is an internal rearrangement of TIBU: it carries each TIBU tray to a TIBU tray.
- "jonu" carries each TIBU tray to a TUKI tray.
- "mimu" is an internal rearrangement of TUKI: it carries each TUKI tray to a TUKI tray.
- "pusi" carries each TUKI tray to a GOMU tray.
- "juto" is an internal rearrangement of GOMU: it carries each GOMU tray to a GOMU tray.
- "govu" carries each GOMU tray to a KOSA tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "mago" and then "doku" lands on the same tray as running "mago" alone.
     ("doku" leaves every tray that "mago" produces unchanged.)
R1.2 Running "doku" and then "rifi" gives the same result as running "rifi" alone.
     ("rifi" cannot tell whether "doku" was applied first.)
R1.3 Running "doku" twice in a row leaves every PILO tray exactly where it started.
R2.1 Running "rifi" and then "gamu" lands on the same tray as running "rifi" alone.
     ("gamu" leaves every tray that "rifi" produces unchanged.)
R2.2 Running "gamu" and then "jonu" gives the same result as running "jonu" alone.
     ("jonu" cannot tell whether "gamu" was applied first.)
R2.3 Running "gamu" twice in a row leaves every TIBU tray exactly where it started.
R3.1 Running "jonu" and then "mimu" lands on the same tray as running "jonu" alone.
     ("mimu" leaves every tray that "jonu" produces unchanged.)
R3.2 Running "mimu" and then "pusi" gives the same result as running "pusi" alone.
     ("pusi" cannot tell whether "mimu" was applied first.)
R3.3 Running "mimu" twice in a row leaves every TUKI tray exactly where it started.
R4.1 Running "pusi" and then "juto" lands on the same tray as running "pusi" alone.
     ("juto" leaves every tray that "pusi" produces unchanged.)
R4.2 Running "juto" and then "govu" gives the same result as running "govu" alone.
     ("govu" cannot tell whether "juto" was applied first.)
R4.3 Running "juto" twice in a row leaves every GOMU tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- VUSA has exactly one tray, called n1.
- KOSA has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (PILO, TIBU, TUKI, GOMU):
D1.1 List the trays of PILO in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "doku" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D2.1 List the trays of TIBU in increasing index order q2_1, q2_2, ... in its set line.
D2.2 List the "gamu" table entries in tray order q2_1, q2_2, ..., one entry per tray.
D3.1 List the trays of TUKI in increasing index order q3_1, q3_2, ... in its set line.
