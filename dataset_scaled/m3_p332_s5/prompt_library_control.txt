You are completing the design of a small book sorting row of carts with 5 carts.

The carts are: LOFO, ZOBA, VUGO, BUTU, JOLO. Books move LOFO -> ZOBA -> VUGO -> BUTU -> JOLO.
There are 7 moving steps:
- "sudi" carries each LOFO tray to a ZOBA tray.
- "pulo" is an internal rearrangement of ZOBA: it carries each ZOBA tray to a ZOBA tray.
- "zogi" carries each ZOBA tray to a VUGO tray.
- "paku" is an internal rearrangement of VUGO: it carries each VUGO tray to a VUGO tray.
- "zuti" carries each VUGO tray to a BUTU tray.
- "nisu" is an internal rearrangement of BUTU: it carries each BUTU tray to a BUTU tray.
- "nuva" carries each BUTU tray to a JOLO tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "sudi" and then "pulo" lands on the same tray as running "sudi" alone.
     ("pulo" leaves every tray that "sudi" produces unchanged.)
R1.2 Running "pulo" and then "zogi" gives the same result as running "zogi" alone.
     ("zogi" cannot tell whether "pulo" was applied first.)
R1.3 Running "pulo" three times in a row leaves every ZOBA tray exactly where it started.
R2.1 Running "zogi" and then "paku" lands on the same tray as running "zogi" alone.
     ("paku" leaves every tray that "zogi" produces unchanged.)
R2.2 Running "paku" and then "zuti" gives the same result as running "zuti" alone.
     ("zuti" cannot tell whether "paku" was applied first.)
R2.3 Running "paku" three times in a row leaves every VUGO tray exactly where it started.
R3.1 Running "zuti" and then "nisu" lands on the same tray as running "zuti" alone.
     ("nisu" leaves every tray that "zuti" produces unchanged.)
R3.2 Running "nisu" and then "nuva" gives the same result as running "nuva" alone.
     ("nuva" cannot tell whether "nisu" was applied first.)
R3.3 Running "nisu" twice in a row leaves every BUTU tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- LOFO has exactly one tray, called n1.
- JOLO has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (ZOBA, VUGO, BUTU):
D1.1 ZOBA must be a finite set with at most 1 tray.
D1.2 List the "pulo" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D2.1 VUGO must be a finite set with at most 1 tray.
D2.2 List the "paku" table entries in tray order q2_1, q2_2, ..., one entry per tray.
D3.1 BUTU must be a finite set with at most 1 tray.
D3.2 List the "nisu" table entries in tray order q3_1, q3_2, ..., one entry per tray.

Your task: give one complete concrete design of the middle carts.

Answer format bound: designs with up to 5 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

ZOBA = {q1_1, ..., q1_k}
sudi: n1 -> <ZOBA tray>
pulo: q1_1 -> <ZOBA tray>, ..., q1_k -> <ZOBA tray>
VUGO = {q2_1, ..., q2_k}
zogi: q1_1 -> <VUGO tray>, ... (one entry per ZOBA tray)
paku: q2_1 -> <VUGO tray>, ..., q2_k -> <VUGO tray>
BUTU = {q3_1, ..., q3_k}
zuti: q2_1 -> <BUTU tray>, ... (one entry per VUGO tray)
nisu: q3_1 -> <BUTU tray>, ..., q3_k -> <BUTU tray>
nuva: q3_1 -> <JOLO tray>, ... (one entry per BUTU tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
