You are completing the design of a small book sorting row of carts with 3 carts.

The carts are: MUNA, MOSI, GIJU. Books move MUNA -> MOSI -> GIJU.
There are 3 moving steps:
- "viju" carries each MUNA tray to a MOSI tray.
- "loba" is an internal rearrangement of MOSI: it carries each MOSI tray to a MOSI tray.
- "jomo" carries each MOSI tray to a GIJU tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "viju" and then "loba" lands on the same tray as running "viju" alone.
     ("loba" leaves every tray that "viju" produces unchanged.)
R1.2 Running "loba" and then "jomo" gives the same result as running "jomo" alone.
     ("jomo" cannot tell whether "loba" was applied first.)
R1.3 Running "loba" twice in a row leaves every MOSI tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- MUNA has exactly one tray, called n1.
- GIJU has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle cart (MOSI):
D1.1 List the trays of MOSI in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "loba" table entries in tray order q1_1, q1_2, ..., one entry per tray.

Your task: give one complete concrete design of the middle cart.

Answer format bound: designs with up to 4 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

MOSI = {q1_1, ..., q1_k}
viju: n1 -> <MOSI tray>
loba: q1_1 -> <MOSI tray>, ..., q1_k -> <MOSI tray>
jomo: q1_1 -> <GIJU tray>, ... (one entry per MOSI tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
