You are completing the design of a small book sorting row of carts with 3 carts.

The carts are: NUMI, MAJA, PIDO. Books move NUMI -> MAJA -> PIDO.
There are 3 moving steps:
- "suko" carries each NUMI tray to a MAJA tray.
- "figu" is an internal rearrangement of MAJA: it carries each MAJA tray to a MAJA tray.
- "lofo" carries each MAJA tray to a PIDO tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "suko" and then "figu" lands on the same tray as running "suko" alone.
     ("figu" leaves every tray that "suko" produces unchanged.)
R1.2 Running "figu" and then "lofo" gives the same result as running "lofo" alone.
     ("lofo" cannot tell whether "figu" was applied first.)
R1.3 Running "figu" twice in a row leaves every MAJA tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- NUMI has exactly 3 trays, called n1, n2, n3.
- PIDO has exactly 2 trays, called s1, s2.
- The observed end-to-end behavior of the row sends n1 to s1, n2 to s1, n3 to s1.

Requirements for the middle cart (MAJA):
D1.1 MAJA must be a finite set with at most 3 trays.
D1.2 List the "figu" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D1.3 "suko" must carry different NUMI trays to different MAJA trays.
D1.4 List the "lofo" table entries in MAJA tray order q1_1, q1_2, ...

Your task: give one complete concrete design of the middle cart.

Answer format bound: designs with up to 5 trays in the middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
use tray names q1_1, q1_2, ... for the middle cart):

MAJA = {q1_1, ..., q1_k}
suko: n1 -> <MAJA tray>, n2 -> <MAJA tray>, n3 -> <MAJA tray>
figu: q1_1 -> <MAJA tray>, ..., q1_k -> <MAJA tray>
lofo: q1_1 -> <PIDO tray>, ... (one entry per MAJA tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
