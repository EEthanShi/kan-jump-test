You are completing the design of a small toy sorting line with 3 stations.

The stations are: ZOMI, KOZA, GOJA. Toys move ZOMI -> KOZA -> GOJA.
There are 3 moving steps:
- "sapa" carries each ZOMI slot to a KOZA slot.
- "buni" is an internal reshuffle of KOZA: it carries each KOZA slot to a KOZA slot.
- "doli" carries each KOZA slot to a GOJA slot.

The line's operating rules. These must hold exactly, slot by slot:
R1.1 Running "sapa" and then "buni" lands on the same slot as running "sapa" alone.
     ("buni" leaves every slot that "sapa" produces unchanged.)
R1.2 Running "buni" and then "doli" gives the same result as running "doli" alone.
     ("doli" cannot tell whether "buni" was applied first.)
R1.3 Running "buni" twice in a row leaves every KOZA slot exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- ZOMI has exactly 1 slot, called n1.
- GOJA has exactly 2 slots, called s1, s2.
- The observed end-to-end behavior of the line sends n1 to s1.

Requirements for the middle station (KOZA):
D1.1 List the slots of KOZA in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "buni" table entries in slot order q1_1, q1_2, ..., one entry per slot.
D1.3 List the "sapa" table entries in ZOMI slot order n1.
D1.4 List the "doli" table entries in KOZA slot order q1_1, q1_2, ...

Your task: give one complete concrete design of the middle station.

Answer format bound: designs with up to 3 slots in the middle station
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every slot and every table entry;
use slot names q1_1, q1_2, ... for the middle station):

KOZA = {q1_1, ..., q1_k}
sapa: n1 -> <KOZA slot>
buni: q1_1 -> <KOZA slot>, ..., q1_k -> <KOZA slot>
doli: q1_1 -> <GOJA slot>, ... (one entry per KOZA slot)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
