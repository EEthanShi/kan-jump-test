You are completing the design of a small book sorting row of carts with 3 carts.

The carts are: TUTA, MARO, GUDU. Books move TUTA -> MARO -> GUDU.
There are 3 moving steps:
- "joza" carries each TUTA tray to a MARO tray.
- "vabi" is an internal rearrangement of MARO: it carries each MARO tray to a MARO tray.
- "tudi" carries each MARO tray to a GUDU tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "joza" and then "vabi" lands on the same tray as running "joza" alone.
     ("vabi" leaves every tray that "joza" produces unchanged.)
R1.2 Running "vabi" and then "tudi" gives the same result as running "tudi" alone.
     ("tudi" cannot tell whether "vabi" was applied first.)
R1.3 Running "vabi" three times in a row leaves every MARO tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- TUTA has exactly one tray, called n1.
- GUDU has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle cart (MARO):
D1.1 List the trays of MARO in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "vabi" table entries in tray order q1_1, q1_2, ..., one entry per tray.

Your task: give one complete concrete design of the middle cart.

Answer format bound: designs with up to 5 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

MARO = {q1_1, ..., q1_k}
joza: n1 -> <MARO tray>
vabi: q1_1 -> <MARO tray>, ..., q1_k -> <MARO tray>
tudi: q1_1 -> <GUDU tray>, ... (one entry per MARO tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
