You are completing the design of a small book sorting row of carts with 3 carts.

The carts are: GIVI, DUPU, KONO. Books move GIVI -> DUPU -> KONO.
There are 3 moving steps:
- "lari" carries each GIVI tray to a DUPU tray.
- "jujo" is an internal rearrangement of DUPU: it carries each DUPU tray to a DUPU tray.
- "mila" carries each DUPU tray to a KONO tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "lari" and then "jujo" lands on the same tray as running "lari" alone.
     ("jujo" leaves every tray that "lari" produces unchanged.)
R1.2 Running "jujo" and then "mila" gives the same result as running "mila" alone.
     ("mila" cannot tell whether "jujo" was applied first.)
R1.3 Running "jujo" twice in a row leaves every DUPU tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- GIVI has exactly 2 trays, called n1, n2.
- KONO has exactly 2 trays, called s1, s2.
- The observed end-to-end behavior of the row sends n1 to s1, n2 to s1.

Requirements for the middle cart (DUPU):
D1.1 List the trays of DUPU in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "jujo" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D1.3 List the "lari" table entries in GIVI tray order n1, n2.
D1.4 List the "mila" table entries in DUPU tray order q1_1, q1_2, ...

Your task: give one complete concrete design of the middle cart.

Answer format bound: designs with up to 4 trays in the middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
use tray names q1_1, q1_2, ... for the middle cart):

DUPU = {q1_1, ..., q1_k}
lari: n1 -> <DUPU tray>, n2 -> <DUPU tray>
jujo: q1_1 -> <DUPU tray>, ..., q1_k -> <DUPU tray>
mila: q1_1 -> <KONO tray>, ... (one entry per DUPU tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
