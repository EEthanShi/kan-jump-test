You are completing the design of a small book sorting row of carts with 5 carts.

The carts are: MUNO, DARI, GORI, KUSU, NIKU. Books move MUNO -> DARI -> GORI -> KUSU -> NIKU.
There are 7 moving steps:
- "voki" carries each MUNO tray to a DARI tray.
- "kino" is an internal rearrangement of DARI: it carries each DARI tray to a DARI tray.
- "lino" carries each DARI tray to a GORI tray.
- "rapi" is an internal rearrangement of GORI: it carries each GORI tray to a GORI tray.
- "muja" carries each GORI tray to a KUSU tray.
- "lamo" is an internal rearrangement of KUSU: it carries each KUSU tray to a KUSU tray.
- "puso" carries each KUSU tray to a NIKU tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "voki" and then "kino" lands on the same tray as running "voki" alone.
     ("kino" leaves every tray that "voki" produces unchanged.)
R1.2 Running "kino" and then "lino" gives the same result as running "lino" alone.
     ("lino" cannot tell whether "kino" was applied first.)
R1.3 Running "kino" three times in a row leaves every DARI tray exactly where it started.
R2.1 Running "lino" and then "rapi" lands on the same tray as running "lino" alone.
     ("rapi" leaves every tray that "lino" produces unchanged.)
R2.2 Running "rapi" and then "muja" gives the same result as running "muja" alone.
     ("muja" cannot tell whether "rapi" was applied first.)
R2.3 Running "rapi" twice in a row leaves every GORI tray exactly where it started.
R3.1 Running "muja" and then "lamo" lands on the same tray as running "muja" alone.
     ("lamo" leaves every tray that "muja" produces unchanged.)
R3.2 Running "lamo" and then "puso" gives the same result as running "puso" alone.
     ("puso" cannot tell whether "lamo" was applied first.)
R3.3 Running "lamo" three times in a row leaves every KUSU tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- MUNO has exactly one tray, called n1.
- NIKU has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (DARI, GORI, KUSU):
D1.1 DARI must be a finite set with at most 4 trays.
D1.2 "kino" must NOT be the do-nothing move (it must move at least one DARI tray).
D2.1 GORI must be a finite set with at most 3 trays.
D2.2 "rapi" must NOT be the do-nothing move (it must move at least one GORI tray).
D3.1 KUSU must be a finite set with at most 4 trays.
D3.2 "lamo" must NOT be the do-nothing move (it must move at least one KUSU tray).

Your task: give one complete concrete design of the middle carts.

Answer format bound: designs with up to 5 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

DARI = {q1_1, ..., q1_k}
voki: n1 -> <DARI tray>
kino: q1_1 -> <DARI tray>, ..., q1_k -> <DARI tray>
GORI = {q2_1, ..., q2_k}
lino: q1_1 -> <GORI tray>, ... (one entry per DARI tray)
rapi: q2_1 -> <GORI tray>, ..., q2_k -> <GORI tray>
KUSU = {q3_1, ..., q3_k}
muja: q2_1 -> <KUSU tray>, ... (one entry per GORI tray)
lamo: q3_1 -> <KUSU tray>, ..., q3_k -> <KUSU tray>
puso: q3_1 -> <NIKU tray>, ... (one entry per KUSU tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
