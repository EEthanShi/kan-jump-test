You are completing the design of a small book sorting row of carts with 5 carts.

The carts are: VIPI, VUBU, FOKA, POLU, MOTO. Books move VIPI -> VUBU -> FOKA -> POLU -> MOTO.
There are 7 moving steps:
- "fido" carries each VIPI tray to a VUBU tray.
- "fodu" is an internal rearrangement of VUBU: it carries each VUBU tray to a VUBU tray.
- "vuzo" carries each VUBU tray to a FOKA tray.
- "sibo" is an internal rearrangement of FOKA: it carries each FOKA tray to a FOKA tray.
- "jaro" carries each FOKA tray to a POLU tray.
- "jivo" is an internal rearrangement of POLU: it carries each POLU tray to a POLU tray.
- "nivo" carries each POLU tray to a MOTO tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "fido" and then "fodu" lands on the same tray as running "fido" alone.
     ("fodu" leaves every tray that "fido" produces unchanged.)
R1.2 Running "fodu" and then "vuzo" gives the same result as running "vuzo" alone.
     ("vuzo" cannot tell whether "fodu" was applied first.)
R1.3 Running "fodu" three times in a row leaves every VUBU tray exactly where it started.
R2.1 Running "vuzo" and then "sibo" lands on the same tray as running "vuzo" alone.
     ("sibo" leaves every tray that "vuzo" produces unchanged.)
R2.2 Running "sibo" and then "jaro" gives the same result as running "jaro" alone.
     ("jaro" cannot tell whether "sibo" was applied first.)
R2.3 Running "sibo" twice in a row leaves every FOKA tray exactly where it started.
R3.1 Running "jaro" and then "jivo" lands on the same tray as running "jaro" alone.
     ("jivo" leaves every tray that "jaro" produces unchanged.)
R3.2 Running "jivo" and then "nivo" gives the same result as running "nivo" alone.
     ("nivo" cannot tell whether "jivo" was applied first.)
R3.3 Running "jivo" twice in a row leaves every POLU tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- VIPI has exactly one tray, called n1.
- MOTO has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (VUBU, FOKA, POLU):
D1.1 VUBU must be a finite set with at most 4 trays.
D1.2 "fodu" must NOT be the do-nothing move (it must move at least one VUBU tray).
D2.1 FOKA must be a finite set with at most 3 trays.
D2.2 "sibo" must NOT be the do-nothing move (it must move at least one FOKA tray).
D3.1 POLU must be a finite set with at most 3 trays.
D3.2 "jivo" must NOT be the do-nothing move (it must move at least one POLU tray).

Your task: give one complete concrete design of the middle carts.

Answer format bound: designs with up to 4 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

VUBU = {q1_1, ..., q1_k}
fido: n1 -> <VUBU tray>
fodu: q1_1 -> <VUBU tray>, ..., q1_k -> <VUBU tray>
FOKA = {q2_1, ..., q2_k}
vuzo: q1_1 -> <FOKA tray>, ... (one entry per VUBU tray)
sibo: q2_1 -> <FOKA tray>, ..., q2_k -> <FOKA tray>
POLU = {q3_1, ..., q3_k}
jaro: q2_1 -> <POLU tray>, ... (one entry per FOKA tray)
jivo: q3_1 -> <POLU tray>, ..., q3_k -> <POLU tray>
nivo: q3_1 -> <MOTO tray>, ... (one entry per POLU tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
