You are completing the design of a small book sorting row of carts with 3 carts.

The carts are: PAJO, NORI, SIZA. Books move PAJO -> NORI -> SIZA.
There are 3 moving steps:
- "laju" carries each PAJO tray to a NORI tray.
- "zifo" is an internal rearrangement of NORI: it carries each NORI tray to a NORI tray.
- "dini" carries each NORI tray to a SIZA tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "laju" and then "zifo" lands on the same tray as running "laju" alone.
     ("zifo" leaves every tray that "laju" produces unchanged.)
R1.2 Running "zifo" and then "dini" gives the same result as running "dini" alone.
     ("dini" cannot tell whether "zifo" was applied first.)
R1.3 Running "zifo" twice in a row leaves every NORI tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- PAJO has exactly 1 tray, called n1.
- SIZA has exactly 2 trays, called s1, s2.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle cart (NORI):
D1.1 NORI must be a finite set with at most 2 trays.
D1.2 List the "zifo" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D1.3 List the "laju" table entries in PAJO tray order n1.
D1.4 Every SIZA tray must be reached by "dini" from at least one NORI tray.

Your task: give one complete concrete design of the middle cart.

Answer format bound: designs with up to 3 trays in the middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
use tray names q1_1, q1_2, ... for the middle cart):

NORI = {q1_1, ..., q1_k}
laju: n1 -> <NORI tray>
zifo: q1_1 -> <NORI tray>, ..., q1_k -> <NORI tray>
dini: q1_1 -> <SIZA tray>, ... (one entry per NORI tray)

Every rule and requirement above must hold exactly for your tables. Do not
explain; output only the lines in the format above.
