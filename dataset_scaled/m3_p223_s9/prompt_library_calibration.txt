You are completing the design of a small book sorting row of carts with 5 carts.

The carts are: GOJO, ZOKA, SOKA, SIZU, ZOZI. Books move GOJO -> ZOKA -> SOKA -> SIZU -> ZOZI.
There are 7 moving steps:
- "sigo" carries each GOJO tray to a ZOKA tray.
- "nora" is an internal rearrangement of ZOKA: it carries each ZOKA tray to a ZOKA tray.
- "pado" carries each ZOKA tray to a SOKA tray.
- "buvi" is an internal rearrangement of SOKA: it carries each SOKA tray to a SOKA tray.
- "lara" carries each SOKA tray to a SIZU tray.
- "vupu" is an internal rearrangement of SIZU: it carries each SIZU tray to a SIZU tray.
- "juji" carries each SIZU tray to a ZOZI tray.

The row's operating rules. These must hold exactly, tray by tray:
R1.1 Running "sigo" and then "nora" lands on the same tray as running "sigo" alone.
     ("nora" leaves every tray that "sigo" produces unchanged.)
R1.2 Running "nora" and then "pado" gives the same result as running "pado" alone.
     ("pado" cannot tell whether "nora" was applied first.)
R1.3 Running "nora" twice in a row leaves every ZOKA tray exactly where it started.
R2.1 Running "pado" and then "buvi" lands on the same tray as running "pado" alone.
     ("buvi" leaves every tray that "pado" produces unchanged.)
R2.2 Running "buvi" and then "lara" gives the same result as running "lara" alone.
     ("lara" cannot tell whether "buvi" was applied first.)
R2.3 Running "buvi" twice in a row leaves every SOKA tray exactly where it started.
R3.1 Running "lara" and then "vupu" lands on the same tray as running "lara" alone.
     ("vupu" leaves every tray that "lara" produces unchanged.)
R3.2 Running "vupu" and then "juji" gives the same result as running "juji" alone.
     ("juji" cannot tell whether "vupu" was applied first.)
R3.3 Running "vupu" three times in a row leaves every SIZU tray exactly where it started.

Recorded observations (fixed; your design must reproduce them exactly):
- GOJO has exactly one tray, called n1.
- ZOZI has exactly one tray, called s1.
- The observed end-to-end behavior of the row sends n1 to s1.

Requirements for the middle carts (ZOKA, SOKA, SIZU):
D1.1 List the trays of ZOKA in increasing index order q1_1, q1_2, ... in its set line.
D1.2 List the "nora" table entries in tray order q1_1, q1_2, ..., one entry per tray.
D2.1 List the trays of SOKA in increasing index order q2_1, q2_2, ... in its set line.
D2.2 List the "buvi" table entries in tray order q2_1, q2_2, ..., one entry per tray.
D3.1 List the trays of SIZU in increasing index order q3_1, q3_2, ... in its set line.
D3.2 List the "vupu" table entries in tray order q3_1, q3_2, ..., one entry per tray.

Your task: give one complete concrete design of the middle carts.

Answer format bound: designs with up to 5 trays per middle cart
are well-formed answers (the requirements above may restrict this further).

Answer in exactly this format (listing every tray and every table entry;
for cart number i in the row, use tray names qi_1, qi_2, ...):

ZOKA = {q1_1, ..., q1_k}
sigo: n1 -> <ZOKA tray>
nora: q1_1 -> <ZOKA tray>, ..., q1_k -> <ZOKA tray>

Every rule and requirement above must hold exactly for your tables. Do not
